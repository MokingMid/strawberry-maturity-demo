## 2. 她实际做了什么（从文件还原）

### 2.1 数据收集与标注

- 从图片内容看，检测集是**网络收集的草莓图片**，抽样可见「191农资人」「nipic」「聚荣网」「烘焙茶云彩」等水印，不是自采数据。
- 标注格式是自定义 JSON：每张图一个文件，字段为 `labels[]`，每个框含 `name`、绝对坐标 `x1,y1,x2,y2`，并在每个框里重复记录原图 `size{width,height}`。
- 标注内容 = 检测框 + 逐框成熟度类别，三类：`ripe` / `half` / `unripe`。

### 2.2 分类目录的构造方式

她做的其实是：

1. 按「这张图里所有草莓的类别」把 63 张纯类图各复制一份；
2. 重命名为 `ripe_001.jpg`、`half_001.jpg`、`unripe_001.jpg`；
3. 把对应的检测 JSON 一起复制，并把**所有框的 `name` 统一改成文件夹类别**。

因此 `classification/` 的本质是**整图级的弱标签副本**，不是「一张图一颗草莓」的分类数据集。这个做法有三个直接后果，见 3.4。

### 2.3 传统 CV 流水线（脚本的 6 步）

| 步骤 | 做法 | 参数 |
|---|---|---|
| 1 读取与缩放 | 统一 resize 到 640×480（不保持长宽比） | `TARGET_SIZE=(640,480)` |
| 2 降噪 | 高斯滤波 vs 中值滤波，输出对比图，选中值滤波 | 5×5 |
| 3 颜色空间 | BGR→HSV，拆 H/S/V 三通道 | — |
| 4 颜色掩码 | 深红 + 淡粉合成「红果掩码」；黄绿单列作「未熟掩码」 | 深红 H∈[0,22]∪[165,180]、S≥90、V≥60；淡粉 S∈[30,90]、V≥150；黄绿 H∈[18,60] |
| 5 形态学 | 开运算去噪 → 闭运算填孔 → 大核开运算「切」细突起 | 开 3×3、闭 5×5；红果切核 89×89（半径 44）；绿果切半径为 0（等于不切） |
| 6 轮廓 | `findContours` + 面积过滤 → 单果框/质心/占比 | 最小面积 400 px（640×480 下约 0.13%） |

输出物料很完整：每张图 14 张中间过程图、一张流水线拼图、单果裁剪、以及一份 431 行的 CSV（面积、框、质心、深红/淡粉/绿占比、熟度）。

### 2.4 熟度判定规则（脚本内）

对每个轮廓区域内：

1. 绿占比 ≥ 0.5 → 未熟；
2. 否则深红占比 ≥ 0.5 → 成熟；
3. 否则 → 半熟。

这套规则在「区域裁对了」时是有效的（见 3.5），但绿色掩码把叶子也算进来，导致大量误检。

### 2.5 她得出了什么结论

- CSV 统计：431 个轮廓，其中成熟 48、半熟 3、未熟 380。
- 对比图里确实做了「高斯 vs 中值」「3×3 vs 5×5」的视觉对比，注释里写「经数据对比选定」。
- 但没有留下任何阈值/核尺寸的对比表格，也没有用标注框算过精度。

| 框是否越界/退化 | 0 个 |
| 是否有重复框（IoU>0.7） | 0 对 |
| 是否有过小框（<0.2% 面积） | 0 个 |

| 贴边裁切的框 | 15 个（可能是果实被画面截断，需确认标注规范） |

结论：**结构层面是干净的**，可以直接做格式转换。

### 3.2 标注内容：4 个问题

1. **`image_024` 整张错位（严重）**
   - 它和 `image_001` 是同一场景的水平翻转（尺寸相同、像素级镜像一致）。
   - 但 3 个框的坐标与 `image_001` 完全相同，没有做镜像变换，实际全部落在左侧叶片上；类别还被改成了 `half`，其中一个写成 `hslf`。
   - 叠加框检查：3 个框内红色占比为 0，绿色占比高，确认错位。
   - 影响：这 3 个框既污染检测标注，也污染 `half` 类统计。
2. **类别拼写错误**：`image_024.json` 中有 1 个 `hslf`，应为 `half`。
3. **少量疑似类别噪声**：`image_040`、`image_053`、`image_060` 各有 1 个 `unripe` 框内红色占比 >0.5（分别为 0.60/0.51/0.51），建议人工复核是否为未熟/成熟边界样本。
4. **半熟定义没有成文**：从图像看，`half` 指「果实部分转色、红白过渡」，但边界（红色覆盖多少算成熟）没有写下来；`image_001`（检测标 ripe）与 `half_001`（分类目录标 half）就是同一个场景的两种判断，说明边界确实模糊。

其余标注质量良好（用颜色统计间接验证）：

| 类别 | 框数 | 框内红色占比（均值） | 框内绿色占比（均值） |
|---|---|---|---|
| ripe | 73 | 0.77 | 0.12 |
| unripe | 96 | 0.07 | 0.75 |
| half | 14 | 0.52 | 0.30 |

`ripe` 框基本是红的、`unripe` 框基本是绿的，说明**绝大多数框是贴合的**。

| `image_014` ↔ `image_062` | 水平翻转，框已正确镜像 | 都是 unripe |
| `image_021` ↔ `image_049` | 同图，框位置略有差异 | 都是 unripe |

| 检查项 | 结果 |

| 是否单果图 | 否。51/63 张含 ≥2 颗草莓（2–8 颗） |

### 3.5 传统流水线：可作为对照实验，但不能当检测器

用她的 `轮廓信息.csv` 对照 183 个标注框（先把 640×480 坐标按原图尺寸还原）：

| 指标 | IoU≥0.3 | IoU≥0.5 |
|---|---|---|
| TP / FP / FN | 87 / 344 / 96 | 54 / 377 / 129 |
| 精确率 P | **0.202** | **0.125** |
| 召回率 R | **0.475** | **0.295** |
| 匹配框上的类别一致率 | 95.4%（83/87） | 100%（54/54） |

解读：

- **「区域对了，颜色判熟度是准的」**——匹配上的框类别一致率 95%+，说明 HSV 占比规则本身有效。
- **「区域经常不对」**——431 个输出 vs 183 个真值，59/64 张图的目标数不一致；精确率只有 0.20。
- 误检/多检的主要来源：
  1. **黄绿掩码把叶片算成果实**（未熟 380 个 vs 真值 96 个）。绿果切半径为 0，等于完全不切，叶片形状又足够大，面积过滤拦不住。例：`image_039` 真值 5 个，算法输出 13 个，多出来的都是叶子。
  2. **肤色/背景被红/粉阈值命中**。例：`image_023`（手托一颗白草莓，真值 1 个）输出了 6 个框，其中 500×667 的原图里手部区域被当成红果，导出的 `image_023_berry00.png` 就是一块手掌。
  3. **相邻草莓粘连未切开**。例：`image_001` 前两颗被合成一个轮廓，导出的 `image_001_berry00.png` 里是两颗草莓。
  4. **背景碎片**：431 个框中 73 个小于画面 0.5%，预测框面积中位数 1.7%，真值中位数 11.4%，说明大量小碎片混入。
- 注意：类别一致率这个指标**偏乐观**，因为匹配时优先选了同类框；它只能说明「区域内颜色规则可用」，不能当分类精度。

**结论**：这套流水线适合作为报告里的「传统颜色分割基线 / 失败案例分析」，不适合作为系统的检测器，也不能把它输出的 431 张裁剪图当分类训练集。

## 5. 开工前必须拍板的 5 个决策

> 这 5 个问题不先定，后面的转换和划分会白做。建议组内 30 分钟内定完并写进数据卡。

**D1. 类别体系用 3 类还是 4 类？**

- 开题口径是 4 类（未熟/成熟/过熟/损坏），现有数据只有 3 类（未熟/成熟/半熟），**「半熟」不等于「过熟」**，也没有损坏样本。
- 推荐：**主线先按 3 类做，报告里明确写「受数据限制，本组实际评估 3 状态；过熟/损坏作为后续扩展」**。
- 若老师要求必须 4 类：需要补标过熟与损坏样本（至少每类 30–50 框、15 个以上场景），否则不要声称做了 4 类。
- 时间紧的退化方案：**2 类（ripe/unripe）**，把 half 从检测中剔除或并入 ripe，分类任务最稳。

**D2. 「半熟」的判定标准写死**

- 建议规则：果面红色覆盖 <1/2 且明显转色 → half；≥1/2 → ripe；基本无红 → unripe。
- 定完后回查现有 14 个 half 框（尤其 `image_001`/`half_001` 冲突、`image_024`）。
- 边界样本单列「困难样本」清单，报告里说明处理方式。

**D3. 分类器输入用整图还是 ROI？**

- 推荐 **ROI**：用检测框（可外扩 10%–15%）裁剪单果，分类器只看一颗草莓。这与开题的两阶段路线一致。
- 整图分类只适用于「一图一果」，而当前 51/63 张是多果，不成立。

**D4. 数据来源与自采**

- 现有图是网络图且带水印，需在报告写清来源与用途（课程学习），不要声称自采。
- 计划里的 50–100 张自采测试集建议保留：同一手机、俯拍、不同光照，单独作为泛化测试集，不参与训练。

**D5. `classification/` 目录怎么处理？**

- 推荐：**归档不再使用**，按检测框重建 `crops_v1/`。
- 如果队友坚持保留，必须至少做到：只保留单果图、按逐框标签分类、与检测集同源同划分；否则不要进训练。

### 各阶段的注意点

**P0 冻结**

- 现在的路径 `dataset (2)` 带空格和括号，命令行和部分库容易出问题，改成 `strawberry_v1`。
- 根目录的 `dataset (2)`、`caomei/caomei/dataset (2)`、两个 zip 三选一，其余归档到 `_archive/`，不要留在工作路径里。
- `archive.zip`（苹果/香蕉/番茄 4,614 张）先单独放，不要混进草莓数据；是否用于分类预训练，等 P1 决策后再定。

**P1 修标签**

- `image_024` 两种处理：直接删除（推荐，因为它只是 `image_001` 的翻转副本），或重新镜像 3 个框并保留。**不要保留现在的错框**。
- `hslf` 改 `half`。
- 3 个红色偏高的 unripe 框逐个看图确认，是标签错还是光照/品种导致。
- 15 个贴边框确认策略：允许截断（YOLO 可训）还是排除（分类裁剪不用）。
- 写一页标注规范：类别定义、遮挡>50% 不标、贴边处理、边界样本清单。

**P2 转格式**

- 转换时保留一份「框中心/宽高」的校验清单；转换后**必须把 64 张图全部回绘一遍**，人工抽查至少 15 张。
- 类别顺序固定：如 `0=ripe, 1=half, 2=unripe`，写进 `data.yaml` 和数据卡，别在不同脚本里换顺序。
- 建议同时保留原始 JSON（只读），转换产物单独目录，避免来回覆盖。

**P3 划分**

- 64 张图、57 个独立场景。按场景分组后再分层，别按图片随机抽。
- 建议比例 7:1.5:1.5 ≈ **40/8/9 个场景组**；half 只有 3 个独立场景，临时按 1/1/1 分配以保证三集都有 half 可评估（训练集只有 1 个 half 场景，模型学不到，必须补采后再做最终划分）。
- 划分清单（图片名、场景组、类别构成、split）落成 CSV，之后所有实验引用同一份清单。
- 如果后续补数据，只往训练集加；测试集冻结，不再动。

**P4 ROI 分类集**

- 只用 GT 框裁，**不要用她算法输出的 431 张**（含叶片、手、粘连）。
- 外扩 10%–15% 保留少量背景，但对多果图要检查外扩后是否带入邻果；带入明显邻果的降低外扩或直接剔除。
- 分类集数量预估：ripe 73、unripe 96、half 14，扣除贴边/遮挡/重复后约 150–170 个可用样本；**half 仍然很少**。
- half 数据不足的处置优先级：① 补采/补标 half 场景；② 强增强 + 类别权重；③ 降级为 2 类。三选一，写进报告。

**P5 传统基线**

- 只在 val/test 上评测，且用与深度学习相同的测试集，才能对照。
- 报告三张表：降噪对比、形态学核尺寸对比、检测效果对比（P/R/F1 per class）。
- 失败案例图直接用 `image_001`（粘连）、`image_023`（肤色）、`image_039`（叶片），很有说服力。
- 明确写出「传统颜色分割的瓶颈在分割而非分类」——这是你们对照实验的结论，不是缺点。

**P6 训练**

- 检测：640 输入，3 类；增强用翻转、缩放、轻度 HSV，**不要大幅色相抖动**（颜色就是成熟度线索）。
- 分类：224 输入，迁移学习；half 类用重采样/类别权重；验证集看宏 F1 和混淆矩阵，不只看准确率。
- 记录每次实验的数据版本与划分版本，避免「用哪份数据训的」说不清。

**P7 系统与自采**

- 自采测试集单独目录、单独标注，绝不能被划分脚本扫进训练集。
- 视频 Demo 先跑通「检测→裁剪→分类→计数」，跟踪和虚拟分拣线作为展示层，别反过来拖累主线。

## 9. 风险与报告口径

| 风险 | 说明 | 应对 |
|---|---|---|
| 数据量太小 | 64 图 / 183 框，检测容易过拟合；57 个独立场景 | 强增强；补数据；报告里如实说明；测试集独立 |

| 重复图泄漏 | 7 对翻转/缩放副本 | 按场景分组划分，禁止跨集 |
| 网络图来源 | 带水印、许可不明、场景单一 | 数据卡写明来源与用途；补自采测试 |

1. 「检测数据为 64 张公开网络图像、183 个标注框，按场景去重后 57 个独立场景。」
2. 「成熟度按数据现状分为未熟/半熟/成熟 3 类；开题中的过熟/损坏因缺少样本，作为后续扩展。」
3. 「传统 HSV 颜色分割作为对照基线，其瓶颈在分割；深度学习主线在相同测试集上评估。」
