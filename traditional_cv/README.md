# 传统 HSV 预处理流水线（对照基线）

本目录保留队友编写的传统图像处理脚本与已产出的结果。它不是深度学习训练数据的准备脚本，而是**课程要求中的传统预处理演示 + 对照实验基线**。

## 脚本做了什么

`strawberry_preprocess.py` 对 `../datasets/strawberry_v1/detection/images/` 的 64 张图执行 6 步：

1. resize 到 640×480；
2. 高斯滤波 vs 中值滤波（选定 5×5 中值）；
3. BGR→HSV，拆 H/S/V；
4. 三套颜色掩码：深红 + 淡粉 = 红果；黄绿 = 未熟；
5. 形态学：开运算 3×3 → 闭运算 5×5 → 大核开运算切细突起（红果半径 44，绿果不切）；
6. `findContours` + 面积过滤（≥400 px），输出单果框、质心、颜色占比与熟度。

判定规则：绿占比 ≥0.5 → 未熟；否则深红占比 ≥0.5 → 成熟；否则半熟。

输出 431 个轮廓 vs 真值 183 个；59/64 张图的目标数不一致。

## 主要失败模式

1. **叶片被当成未熟果**：黄绿掩码把叶片算进来，绿果切半径为 0（等于不切），面积过滤拦不住。例：`image_039` 真值 5 颗，输出 13 个。
2. **手部/肤色被红粉阈值命中**：例：`image_023`（手托一颗白草莓）输出 6 个框，其中包含手掌区域。
3. **相邻草莓粘连**：`image_001` 前两颗被合成一个轮廓。
4. **背景碎片**：431 个框中 73 个小于画面 0.5%，预测框面积中位数 1.7%，真值中位数 11.4%。

## 使用警告

- `output/单果区域/` 的 431 张裁剪来自算法轮廓，**不是**标注框，含叶片、手部、粘连、背景碎片；**不能**用于训练分类器。
- 单果分类集必须用 `../datasets/strawberry_v1/detection/labels/` 的 GT 框重新裁剪。
- 报告里可以把本目录作为“传统颜色分割基线”，重点写“分割是瓶颈、颜色判熟度本身是准的（匹配框类别一致率 95%+）”，不要把 431 个输出当成检测结果。
